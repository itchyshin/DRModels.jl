- **Gaussian `phylo(1 | g)` with a constant `sigma` now reports `sd_phylo` on the tip-correlation scale, the same as `sigma ~ 1 + x` and drmTMB (#979).** On a tree whose height is not 1 the sparse `sigma ~ 1` route returned the raw branch-length scale (`log sd_phylo` -1.2917751 on `ade4::carni70`, height 53.8) while the dense route returned the correlation scale; `sigma ~ 1` now gives 0.7008616, drmTMB's value, with the log-likelihood unchanged. An ultrametric tree is fitted at unit height (an exact reparameterisation) and the fit records `phylo_scale = :correlation`, so `re_sd(fit; scale = :drmtmb)` is a no-op there and the tree-height warning no longer fires. A non-ultrametric tree cannot be standardised by one rescaling, so it stays on the raw scale with the warning. The same applies to `method = :REML`, `algorithm = :em`, and to `drm_phylo_penalty(sd_u = ...)`, which is now read on the correlation scale on this route. Code that multiplied `re_sd(fit)` by `sqrt(phylo_tree_height(tree))` on this route must drop that factor.
