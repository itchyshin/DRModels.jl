- **Behaviour change: `weights` must have one value per row of `data` on every route.** `drm(...; weights = w)` now refuses a vector whose length differs from the number of rows of `data`, with a `DimensionMismatch` that says one weight per data row is needed. Before, the fixed-effect univariate routes (Gaussian, LogNormal, Gamma, Student, SkewNormal, Poisson, NegBinomial2, TruncatedPoisson, Beta, Binomial, BetaBinomial, ZeroOneBeta, Tweedie, CumulativeLogit) also accepted a vector already cut to the rows kept after rows with a missing response or predictor were dropped. That gives a wrong likelihood when the cut vector is misaligned with the kept rows, and drmTMB refuses it too ("`weights` must have one value per row of `data`"). A vector with one weight per row of `data` still works as before: the dropped rows take their weights with them. Code that passed `weights(fit)` (which holds the kept rows only) back to `drm` with the original data must now pass the full-length vector, or drop the incomplete rows first with `drm_listwise`. Routes that take no weights at all refuse a wrong length with the same message and keep their own refusal for a full-length vector. This includes `update(fit, formula; data, weights = weights(fit))` on a fit that dropped rows. Bootstrap refits (`bootstrap_summary`, `bootstrap_ci`) pass the right weights themselves.
