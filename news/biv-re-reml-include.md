- The bivariate `(1 | p | g)` route accepts `method = :REML` together with `miss_control(response = "include")`, which goes beyond drmTMB 0.8.1: drmTMB refuses REML for bivariate fits with kept missing responses ("`REML` is not implemented with explicit missing-data engines yet"). The fit is the restricted likelihood of the observed entries; it equals a dense computation of that likelihood to 1e-8 and an independent `nlme::lme` REML fit of the same model to 1e-5 in the log-likelihood. Three safeguards come with it. (1) REML now refuses by name when the fixed-effect design of the observed entries of a response is rank-deficient, for example a covariate or factor level that is constant, aliased, or present only in rows whose response is missing (or whose weight is 0); the message names REML, the response, the aliased columns, and the options that fit the cause (remove or recode the term, use `method = :ML`, and for a factor level seen only in rows with a missing response also take those rows out of `data`, which the default `miss_control(response = "drop")` does, and for a level lost only through weight 0 give those rows a positive weight). Before, such a fit stopped with a raw `SingularException: matrix is singular; factorization failed`. (2) The documentation states the missing-at-random assumption that the kept rows rely on. (3) The documentation states that a REML log-likelihood is comparable only between fits with the same fixed effects and the same used entries, so a fit with kept rows is not comparable with a complete-case fit, REML values should not be used for likelihood-ratio tests of fixed effects, and rescaling a predictor column by `s` shifts the REML log-likelihood by `-log(s)`. `method = :ML` is unchanged.
