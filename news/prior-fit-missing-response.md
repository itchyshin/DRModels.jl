- **A fit with priors and a `missing` response now stops with a clear error instead of a raw `MethodError`.** `drm(...; priors = ...)` (a prior table or `drm_priors`, Gaussian including phylogenetic SD regression, or binomial; also `resolve_priors`, `update` and `miss_control(response = "include")`) already refused a `NaN` response with "requires complete responses"; a response column holding `missing` reached a `Vector{Float64}` conversion first and failed with `MethodError: Cannot convert an object of type Missing to an object of type Float64`. Both now give the same `ArgumentError`. Fits without priors are unchanged: they still drop the incomplete rows and report the count. drmTMB 0.8.1 also refuses incomplete data when `priors` is given, and asks for the incomplete rows to be removed explicitly. Test: `test/test_prior_table_missing_response.jl`.
