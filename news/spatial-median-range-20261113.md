- **`spatial(1 | g)` with `coords` now fixes the range at the median distance, as drmTMB does.** The kernel is `exp(-d / m) + 1e-6 I`, where `m` is the median positive pairwise distance between sites (the maximum distance if the median is zero). The range is fixed, not estimated. Two routes changed, so existing fits on them give different numbers:
  - Gaussian `spatial(1 | g)` (ML) used to estimate the range as one more parameter. It now has no `:range` block, one parameter fewer, and a different log-likelihood and spatial SD. `method = :REML` is no longer refused on this route and matches drmTMB (`REML = TRUE`).
  - Binomial `spatial(1 | g)` and `spatial(0 + x | g)` (with an `sd()` formula or the bare form) used the mean pairwise distance and a 1e-8 ridge. They now use the median kernel. This also applies to `bootstrap` and `simulate` on these fits.
  Example (20 sites, 6 rows per site; test data in `test/fixtures/spatial_median_range/`): see the table in the pull request. Every other `spatial()` route (Poisson, NB2, Gamma, Beta, Student, bivariate) already used this kernel. If you need the old estimated-range fit, a bare `spatial()` no longer gives it; pass a covariance matrix with `relmat(1 | g)` and `K = ...` for a kernel of your own range. The fit stores the fixed range: the printed summary shows a line "Spatial range = ... (fixed at the median distance between sites, as drmTMB; not estimated)" and `coef(fit, :range)` returns it (a one-element vector on the distance scale). It is not a parameter, so it is not in `coef(fit)`, `vcov`, `stderror`, `dof` or `aic`.
